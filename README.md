# cpp-compendium

> **C++で一生食べていくための、動くコード付きリファレンス**

プログラミング未経験の人が最初に読むクイックガイドであり、C++を一通り学んだ人が「あれ何だっけ」と思ったときに戻ってくる場所です。基本文法からSIMD最適化、バイナリ解析まで、実務や巨大OSSで出会う知識をこのリポジトリに集約します。

C++全般の学習に使える内容を目指しつつ、**Unreal Engineでのゲーム開発と、ゲームエンジン開発に役立つ知識**を軸に整理します。

---

## このプロジェクトについて

- **主な読者は自分自身**です。長く読み返し、長くメンテナンスすることを前提に書きます。
- 公開リポジトリとして、他の人の役にも立てば嬉しいと考えています。
- **教科書としても辞典としても使えること**を目指します。
  - **通読ルート**：Partを順に読めば、未経験から実務レベルまで到達できます。
  - **逆引き**：「ムーブ後のオブジェクトはどうなる？」「false sharingとは？」のように、知りたい項目から直接引けます。
- バージョン番号（v1.0など）は付けません。気軽に追記・整理し、いつでも振り返れる状態を保つことを優先します。

## 目的

**C++エンジニアとして長くキャリアを歩むための土台を作ること。**

具体的には、レベルの高いゲーム会社のクライアントエンジニアとして、ゲームエンジン開発・VFX・AI開発など、**どの領域に配属されても必ず役に立つC++の力**を身につけ、維持することを目指します。

そのために、次の状態を作ります。

1. **「知らない」を「ちょっと知っている」にする**
   実務や巨大OSSで出会う概念に、一度は触れておきます。
2. **「ちょっと知っている」から「実際に対応できる」へすぐ戻れるようにする**
   読み返せば、要点・落とし穴・動くコードがすぐに手に入る状態にしておきます。
3. **必要なときに深く掘れる入口を用意する**
   規格の条項、コンパイラの挙動、アセンブリ、参考文献へたどれるようにします。

### ゲーム開発という軸

トピックを選ぶとき、深さを決めるときは、次の2つの場面で役立つかどうかを優先します。

- **Unreal Engineでのゲーム開発**：UE C++の方言（UObject、リフレクションマクロ、独自コンテナ、GC）を、標準C++との違いとあわせて理解し、エンジンのソースコードを読めるようになること
- **ゲームエンジン開発**：メモリ管理、データ指向設計、ジョブシステム、SIMD、フレーム予算を意識した最適化など、エンジンを支える技術を理解し、自分で実装できるようになること

各章の「🏭 実務・OSSではこう使われる」では、可能な限りUnreal Engineやゲームエンジンでの実例を取り上げます。

## 扱う範囲・扱わない範囲

### 扱う

- C++の言語仕様と標準ライブラリ（C++20を基準に、C++23以降も扱う）
- ビルド、ツールチェーン、デバッグ、テスト、静的解析
- 設計、イディオム、API設計、エラー処理
- 並行・並列処理とメモリモデル
- メモリ、キャッシュ、パフォーマンス最適化、SIMD
- 逆アセンブル、バイナリ解析、脆弱性の発見と対策
- 大規模開発（CMake、パッケージ管理、ABI、クロスプラットフォーム）
- Unreal Engine C++と標準C++の違い

### 扱わない

- Qtなど、特定のGUIフレームワーク
- 組込み固有の話題
- C++98時代の書き方の詳説（必要な箇所で「昔はこうだった」と触れる程度）
- グラフィックスAPI（Vulkan / DirectX など）そのもの
- アルゴリズム・データ構造の理論（LeetCode的な内容）

## レベル別ガイド

章と項目には4段階のレベルを付けます。

| レベル | 表記 | 対象者 |
|---|---|---|
| 入門 | ★☆☆☆ | プログラミング自体が未経験 |
| 基礎 | ★★☆☆ | 他の言語は書けるが、C++はほぼ未経験 |
| 実務 | ★★★☆ | C++を一通り書ける。実務経験がある、またはC++を一度学んだことがある |
| 専門 | ★★★★ | 性能・設計・安全性に責任を持つ立場 |

### 入門 ★☆☆☆

- **読む場所**：Part 0（プログラミング入門）から順に通読し、各章の「📘 基本」を読む
- **到達条件**
  - 変数・条件分岐・繰り返し・関数を使った小さなプログラムを、自分で書いて動かせる
  - コンパイルエラーのメッセージを読み、自力で修正できる
  - 「ソースコードがコンパイルされて実行ファイルになる」流れを説明できる

### 基礎 ★★☆☆

- **読む場所**：Part 1〜4の通読ルートと、各章の「📘 基本」
- **到達条件**
  - CMakeでプロジェクトをビルドし、デバッガでステップ実行できる
  - RAIIとスマートポインタを使って、所有権を説明できる
  - 用途に合った標準コンテナとアルゴリズムを選べる
  - よくある未定義動作（UB）を知っており、避けられる

### 実務 ★★★☆

- **読む場所**：各章の「⚡ 30秒で思い出す」「⚠️ 落とし穴とUB」と、早見表
- **到達条件**
  - ムーブセマンティクス、テンプレート、conceptsを使った設計ができる
  - 主要なイディオム（PImpl、CRTP、型消去など）を場面に応じて使い分けられる
  - コードレビューで、寿命・例外安全性・性能上の問題を指摘できる

### 専門 ★★★★

- **読む場所**：各章の「🔬 深掘り」「🏭 実務・OSSではこう使われる」、Part 7以降、ベンチマーク結果
- **到達条件**
  - C++のメモリモデルを説明し、atomicを正しく使える
  - 生成されたアセンブリを読み、ボトルネックを特定できる
  - SIMD化を行い、その効果をベンチマークで測定・説明できる
  - ABI互換性や大規模ビルドの問題に対処できる
  - 逆アセンブル結果から、プログラムの挙動とコンパイラの最適化を読み解ける
  - メモリ安全性に関わる脆弱性（バッファオーバーフロー、Use-After-Free、整数オーバーフローなど）をソースとバイナリの両面から発見し、修正方法と緩和策を示せる

## 読み方

### 各章の構成

すべての章は、同じテンプレートで書きます。経験者は上の2つだけ読めば思い出せます。初心者は「基本」から読み進められます。

```markdown
# 章タイトル  ★★☆☆  C++11〜

## ⚡ 30秒で思い出す          要点だけ。経験者はここだけ読めばよい
## 📘 基本                    初心者向けの解説
## 🔬 深掘り                  規格の挙動、コンパイラの実装、アセンブリ
## ⚠️ 落とし穴とUB
## 🏭 実務・OSSではこう使われる  LLVM / Chromium / Abseil / Unreal Engine などの実例
## 🦀 Rustとの対応             Rustの知識が助けになる点・罠になる点
## ❓ 思い出しクイズ           読み返したときのセルフチェック
## 📎 参照                    cppreference、規格の条項、講演、書籍
```

### アウトプットの仕組み

インプットだけでなく、アウトプットを重視します。

| 仕組み | 対象 | 内容 |
|---|---|---|
| 思い出しクイズ | **全章で必須** | 読み返したときに理解を確認する問題。解答と解説を付ける |
| compile_failテスト | **全章で必須** | 「このコードはコンパイルできない」ことをテストで保証する。型・concepts・所有権のルールを体で覚えるため |
| ベンチマーク | **パフォーマンスを扱う章で必須** | 「速いらしい」ではなく、計測結果・計測環境・生成アセンブリとともに説明する |
| 実装課題 | 各Partの最後 | 課題文のみを示す。解答は用意しない。実装は別リポジトリで自由に行う |

## 品質の基準

このリポジトリにはバージョンを付けない代わりに、**各章が守るべき基準**を定めます。章ごとに「未着手 / 下書き / 完成」のステータスを付け、次をすべて満たした章を「完成」とします。

- [ ] 章テンプレートのすべての節が埋まっている
- [ ] 本文中のコードは、すべて実際の `.cpp` ファイルから埋め込まれている
- [ ] コード例がGCC / Clang / MSVCのすべてでビルドとテストに通る
- [ ] Sanitizer（ASan / UBSan、並行処理の章はTSan）で問題が出ない
- [ ] compile_failテストが1つ以上ある
- [ ] 思い出しクイズが3問以上ある
- [ ] パフォーマンスを扱う場合、ベンチマークと計測環境が記録されている
- [ ] 参照先（cppreference、規格の条項など）が明記されている

## 技術的な前提

| 項目 | 方針 |
|---|---|
| 基準とするC++ | **C++20**。C++23以降の機能は、章や項目にバージョンのバッジを付けて扱う |

## 使い方

教科書は2通りの方法で読めます。

- **GitHub Pages**：ブラウザで読む（URLは公開後に記載）
- **このリポジトリ**：本文を読みながら、同じ場所にあるコードをビルドして実行する

### 必要なもの

- CMake（3.28以降）とNinja
- GCC / Clang / MSVC のいずれか（C++20対応のもの）
- vcpkg（環境変数 `VCPKG_ROOT` を設定しておく）
- mdBook（手元で教科書をビルドする場合のみ）

### ビルドとテスト

```bash
# 構成（プリセット名は gcc-debug / clang-debug / msvc-debug / clang-asan など）
cmake --preset clang-debug

# 全章をビルドしてテストを実行する
cmake --build --preset clang-debug
ctest --preset clang-debug

# 特定の章だけテストする（例：Part 3 の 02 章）
ctest --preset clang-debug -R p03_02
```

### コード例を1つ実行する

コード例の実行ファイルは `p{Part番号}_{章番号}_{ファイル名}` という名前で作られます。

```bash
# content/p03-ownership/02-move-semantics/examples/basic_move.cpp を実行する
cmake --build --preset clang-debug --target p03_02_basic_move
./build/clang-debug/bin/p03_02_basic_move
```

### 教科書を手元で読む

```bash
mdbook serve --open
```

│   ├── STATUS.md               # 全章の進捗表（スクリプトで自動生成）
│   ├── p00-programming-intro/
│   ├── p01-toolchain/
│   ├── ...
│   ├── p12-unreal-cpp/

├── common/                     # テストとベンチの共通ヘルパー
├── tools/                      # 章の雛形生成、番号の振り直し、STATUS.md生成などのスクリプト

### Partと章

```
content/p03-ownership/
├── README.md                   # Partの概要、到達目標、章の一覧
├── exercises.md                # 実装課題（課題文のみ）
├── 01-raii/
├── 02-move-semantics/
│   ├── README.md               # 本文（章テンプレートに従う。思い出しクイズもここ）
│   ├── CMakeLists.txt          # compendium_chapter() を1行書くだけ
│   ├── examples/               # 本文から埋め込むコード。1ファイル1トピック
│   ├── tests/                  # GoogleTestによるテスト
│   ├── compile_fail/           # コンパイルが失敗することを確かめるコード
│   ├── bench/                  # 性能を扱う章のみ。results/ に計測結果と環境を記録
│   └── asm/                    # 本文で解説するアセンブリの記録（必要な章のみ）
└── 03-smart-pointers/
```

- Partは `p00`〜`p12`、章はPartごとに `01` から番号を振ります。
- 章を途中に差し込むときは、`tools/` の番号振り直しスクリプトを使い、ディレクトリ名・`SUMMARY.md`・本文中のリンクをまとめて更新します。
- compile_failのファイルには、期待するエラーメッセージを先頭に書きます。失敗の理由まで照合し、タイポなど別の理由で失敗しても合格にならないようにします。

  ```cpp
  // EXPECT-ERROR(gcc,clang): use of deleted function
  // EXPECT-ERROR(msvc): attempting to reference a deleted function
  ```

- ベンチマークは、CIではビルドが通ることだけを確認します。計測は手元で行い、CPU・コンパイラ・オプションと一緒に `results/` に記録します。
- Part 10の意図的に脆弱なサンプルは、`COMPENDIUM_BUILD_VULNERABLE=ON` のときだけビルドします。
