# プログラムとは何か

★☆☆☆ 入門　`C++98〜`

> プログラムは、コンピュータにやってほしいことを順番に書いた「命令書」。C++で書いた命令書は、コンパイラによってCPUが直接実行できる機械語に翻訳される。

---

## ⚡ 30秒で思い出す

- **プログラム**は、コンピュータへの命令を順番に並べたもの。命令は**上から順に1つずつ**実行される。
- コンピュータの中心は3つ。**CPU**（命令を実行する）、**メモリ**（実行中のプログラムとデータを置く）、**ストレージ**（ファイルを保存する）。
- CPUが理解できるのは**機械語**だけ。C++で書いた**ソースコード**は、**コンパイラ**が機械語の**実行ファイル**に翻訳する。
- 実行前にまとめて翻訳する言語を**コンパイル言語**と呼ぶ（C++、Rustなど）。実行しながら解釈する言語は**インタプリタ言語**と呼ぶ（Pythonなど）。
- コンパイル言語は実行が速く、ゲームのように性能が重要な分野で使われる。Unreal EngineもC++で書かれている。
- 文法の間違いは、実行する前に**コンパイルエラー**として見つかる。ただし、コンパイルが通っても、プログラムが正しく動くとは限らない。

## 📘 基本

### プログラムは「命令書」

料理のレシピを思い浮かべてください。「玉ねぎを切る」「フライパンで炒める」「塩をふる」と、やることが順番に書いてあります。レシピのとおりに順番に作業すれば、誰でも同じ料理が作れます。

プログラムも同じです。コンピュータにやってほしいことを、順番に書いたものです。違うのは、読み手が人間ではなくコンピュータだという点です。コンピュータは書かれたとおりに正確に、とても速く実行しますが、書かれていないことは一切しません。「だいたいこんな感じで」は通じないので、手順をすべて正確に書く必要があります。

### はじめてのC++プログラム

ゲームで、敵の攻撃を受けて体力（HP）が減る場面をプログラムにしてみます。

```cpp
{{#include examples/first_program.cpp:first_program}}
```

📄 [examples/first_program.cpp](examples/first_program.cpp)

実行結果：

```text
ゲームを開始します
敵の攻撃を受けた！
残りの体力: 70
```

細かい文法は次の章から1つずつ学ぶので、今は雰囲気がつかめれば十分です。

| 行 | 意味 |
|---|---|
| `int main() { ... }` | プログラムを実行すると、ここから始まる |
| `std::cout << "...";` | 画面に文字を表示する |
| `int hp = 100;` | 「hp」という名前の箱を用意して、100を入れておく |
| `hp = hp - damage;` | hp から damage を引いた値を、hp に入れ直す |
| `//` から行末まで | **コメント**。人間向けのメモで、コンピュータは読み飛ばす |
| `;` | 1つの命令（**文**）の終わりを表す |

### 命令は上から順に実行される

プログラムは、書いた順番どおりに実行されます。同じ命令でも、順番を入れ替えると結果が変わります。

```cpp
{{#include examples/order_matters.cpp:power_up_first}}
```

```cpp
{{#include examples/order_matters.cpp:attack_first}}
```

📄 [examples/order_matters.cpp](examples/order_matters.cpp)

実行結果：

```text
=== 攻撃力を上げてから攻撃する ===
敵の残りの体力: 80

=== 攻撃してから攻撃力を上げる ===
敵の残りの体力: 90
```

2つ目では、攻撃力を上げたのは攻撃した**後**なので、攻撃には間に合っていません。プログラムを読むときも書くときも、「この時点で、それぞれの値はいくつか」を順番に追うことが基本になります。

### コンピュータの中身：CPU・メモリ・ストレージ

プログラムを動かす部品は、主に3つです。料理にたとえると、次のようになります。

| 部品 | 役割 | 料理にたとえると | 特徴 |
|---|---|---|---|
| **CPU** | 命令を1つずつ実行する | 料理人 | 1秒間に数十億回の命令を実行できる |
| **メモリ**（RAM） | 実行中のプログラムとデータを置いておく | 調理台 | 読み書きが速い。電源を切ると消える |
| **ストレージ**（SSD など） | ファイルを保存しておく | 冷蔵庫・食品庫 | 電源を切っても残る。メモリより遅い |

プログラムを実行すると、ストレージに保存された実行ファイルがメモリに読み込まれ、CPUがそこから命令を1つずつ取り出して実行します。先ほどの `hp` や `damage` の値も、実行中はメモリに置かれています。

### CPUは機械語しか読めない

CPUが直接理解できるのは、**機械語**と呼ばれる0と1の並びだけです。人間が機械語を直接書くのはとても大変なので、人間が読み書きしやすい**プログラミング言語**でプログラムを書き、それを機械語に翻訳します。

C++のプログラムは、次の流れで実行できる形になります。

```text
  ソースコード              コンパイラ              実行ファイル
  （人間が書く）    ──→    （翻訳する）    ──→    （CPUが実行する）
  first_program.cpp        g++ / clang / MSVC       first_program.exe
```

- **ソースコード**：人間がC++で書いたプログラム。拡張子は `.cpp` が一般的です。
- **コンパイラ**：ソースコードを機械語に翻訳するプログラム。代表的なものに GCC、Clang、MSVC があります。
- **実行ファイル**：機械語に翻訳された結果。Windowsでは `.exe` という拡張子が付きます。

この翻訳作業を**コンパイル**、コンパイルして実行ファイルを作る一連の作業を**ビルド**と呼びます。

### コンパイルエラー：翻訳できないプログラム

文法が間違っていると、コンパイラは翻訳できずに**コンパイルエラー**を出します。たとえば、文の終わりのセミコロン（`;`）を忘れると、次のようになります。

```cpp
int main() {
    int hp = 100 // ここにセミコロンがない
    return hp;
}
```

GCCのエラーメッセージ：

```text
error: expected ',' or ';' before 'return'
```

「`return` の前に `,` か `;` があるはずです」という意味です。エラーメッセージは英語ですが、何行目のどこで、何が足りないかを教えてくれます。エラーが出たら、まずメッセージに書かれた行とその**1つ前の行**を見てください。今回のように、本当の原因は1つ前の行にあることがよくあります。

📄 [compile_fail/missing_semicolon.cpp](compile_fail/missing_semicolon.cpp)

## 🔬 深掘り

### 機械語を覗いてみる

コンパイラが実際にどんな機械語を作るのかを見てみます。2つの数を足すだけの関数です。

```cpp
{{#include examples/add_function.cpp:add}}
```

GCC 13で最適化を有効にしてコンパイルすると、この関数は次の命令になります。機械語の0と1を、人間が読める記号で書いたものを**アセンブリ**と呼びます。

```text
{{#include asm/add_gcc13_O2.s}}
```

📄 [asm/add_gcc13_O2.s](asm/add_gcc13_O2.s)

実質的な命令は `lea`（足し算）と `ret`（呼び出し元に戻る）の2つだけです。C++の1行が、CPUの数個の命令になることがわかります。

自分で試すには、ブラウザで使える [Compiler Explorer](https://godbolt.org/) が便利です。左にC++のコードを書くと、右に機械語がその場で表示されます。詳しくは [Part 1 Compiler Explorerでアセンブリを見る](../../p01-toolchain/12-compiler-explorer/)で扱います。

### コンパイルは実はいくつかの段階に分かれている

「コンパイル」とひとまとめに呼びましたが、実際には次の段階を順に通ります。

1. **プリプロセス**：`#include` などの指示を処理し、ファイルを1つにまとめる
2. **コンパイル**：C++をアセンブリに翻訳する
3. **アセンブル**：アセンブリを機械語（オブジェクトファイル）にする
4. **リンク**：複数のオブジェクトファイルとライブラリをつなぎ合わせ、1つの実行ファイルにする

ここでは「いくつかの段階がある」とだけ覚えておけば十分です。詳しくは [Part 1 コンパイルの仕組み](../../p01-toolchain/01-compilation-model/)で扱います。

### コンパイル言語とインタプリタ言語

| | コンパイル言語 | インタプリタ言語 |
|---|---|---|
| 例 | C++、C、Rust、Go | Python、JavaScript、Ruby |
| 翻訳のタイミング | 実行する前にまとめて翻訳する | 実行しながら1行ずつ解釈する |
| 実行速度 | 速い | 遅い（数倍〜数十倍） |
| 間違いが見つかるタイミング | 多くはコンパイル時 | 多くは実行してその行に来たとき |
| 試しやすさ | ビルドの手間がある | 書いてすぐ実行できる |

実際には、JavaScriptやC#のように、実行中に機械語へ翻訳する（JITコンパイル）言語もあり、境界はあいまいです。

## ⚠️ 落とし穴とUB

### 1. 全角の記号やスペースを混ぜてしまう

日本語入力をオンにしたまま記号を打つと、`；`（全角セミコロン）や `（`（全角かっこ）が入ってしまいます。見た目は似ていても、コンピュータにとってはまったく別の文字なので、コンパイルエラーになります。

```cpp
int hp = 100；   // ✗ 全角のセミコロン
int hp = 100;    // ○ 半角のセミコロン
```

📄 [compile_fail/fullwidth_semicolon.cpp](compile_fail/fullwidth_semicolon.cpp)


このときのエラーメッセージは、「無効な接尾辞」のようにわかりにくいものになります。コンパイラが `100；` を「`100` という数値に、`；` という接尾辞（数値の後ろに付ける印）が付いたもの」と解釈しようとするためです。見慣れないエラーが記号のあたりで出たら、まず全角文字を疑ってください。

| コンパイラ | エラーメッセージ（抜粋） |
|---|---|
| GCC | `unable to find numeric literal operator 'operator""\U0000ff1b'` |
| Clang | `character <U+FF1B> not allowed in an identifier` |
| MSVC | `error C3688: リテラル サフィックス '；' が無効です` |

さらに厄介なのが**全角スペース**（`　`）です。GCCではエラーになりますが、Clangは空白として扱うのでエラーになりません。同じコードがコンパイラによって通ったり通らなかったりするので、全角スペースはコメントの中以外では使わないようにします。エディタの設定で全角スペースを目立たせておくと安心です。

### 2. コンパイルが通れば正しい、とは限らない

コンパイラが見つけられるのは、文法の間違いだけです。たとえば、ダメージを引くつもりで `hp = hp + damage;` と書いても、文法としては正しいのでエラーにはなりません。プログラムは何事もなかったかのように動き、体力が増えてしまいます。

意図どおりに動くかどうかは、実行して確かめる必要があります。このリポジトリが、すべての章でコードを実行してテストしているのはそのためです。

## 🏭 実務・OSSではこう使われる

### ゲームがC++で書かれる理由

Unreal Engineをはじめ、多くのゲームエンジンと家庭用ゲーム機向けのゲームはC++で書かれています。主な理由は次の3つです。

- **速い**：ゲームは、1秒間に60回（1回あたり約16.6ミリ秒）画面を描き直す必要があります。その短い時間に、物理計算、AI、描画の準備をすべて終わらせる必要があるため、コンパイル言語の速さが欠かせません。
- **メモリを細かく制御できる**：ゲーム機のメモリは限られています。C++では、いつ・どこに・どれだけメモリを使うかを自分で決められます。
- **資産と環境**：既存のエンジンやライブラリの多くがC++で書かれており、ゲーム機メーカーの開発キットもC++を前提にしています。

### ビルドには時間がかかる

コンパイル言語の弱点は、ビルドに時間がかかることです。Unreal Engineのような大規模なプロジェクトでは、エンジン全体のビルドに数十分以上かかります。そのため、現場ではビルド時間を短くする工夫が重視されます。これは [Part 1 ビルド時間を短くする](../../p01-toolchain/13-build-times/)で扱います。

## 🦀 Rustとの対応

| 観点 | C++ | Rust |
|---|---|---|
| 言語の種類 | コンパイル言語 | コンパイル言語 |
| コンパイラ | GCC、Clang、MSVC など複数 | rustc（LLVMを使う） |
| ビルドの道具 | CMake、vcpkg など（標準はない） | Cargo（言語に付属） |
| プログラムの開始位置 | `int main()` | `fn main()` |

どちらも実行前に機械語へ翻訳する言語です。大きな違いは、C++には複数のコンパイラがあり、ビルドやパッケージ管理の道具も標準で決まっていない点です。このリポジトリでCMakeとvcpkgを組み合わせているのはそのためです。

## ❓ 思い出しクイズ

**Q1.** プログラムの命令は、どんな順番で実行されますか？

<details>
<summary>答え</summary>

書かれた順番どおり、上から1つずつ実行されます。同じ命令でも、順番を入れ替えると結果が変わることがあります。

</details>

**Q2.** CPU・メモリ・ストレージの役割を、それぞれ一言で説明してください。

<details>
<summary>答え</summary>

CPUは命令を実行する部品、メモリは実行中のプログラムとデータを置いておく場所（電源を切ると消える）、ストレージはファイルを保存しておく場所（電源を切っても残る）です。

</details>

**Q3.** C++で書いたソースコードを、CPUが実行できる形にするのは何という道具ですか？ また、その作業を何と呼びますか？

<details>
<summary>答え</summary>

コンパイラです。ソースコードを機械語に翻訳する作業をコンパイルと呼びます。

</details>

**Q4.** 次のコードはコンパイルできますか？ できる場合、実行するとどうなりますか？

```cpp
int hp = 100;
int damage = 30;
hp = hp + damage;
```

<details>
<summary>答え</summary>

文法は正しいのでコンパイルできます。ただし、ダメージを足しているので体力が130に増えてしまいます。コンパイルが通っても、意図どおりに動くとは限らない例です。

</details>

**Q5.** ゲーム開発でC++が使われる理由を2つ挙げてください。

<details>
<summary>答え</summary>

実行が速いこと（1フレーム約16.6ミリ秒の中で処理を終わらせる必要がある）と、メモリの使い方を細かく制御できることです。既存のエンジンやゲーム機の開発キットがC++を前提にしていることも理由に挙げられます。

</details>
